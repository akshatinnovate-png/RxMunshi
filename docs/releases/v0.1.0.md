# RxMunshi v0.1.0: first working release

**Released 24 November 2026**

RxMunshi is a back-office app for Indian retail pharmacies. It runs on the counter PC or a laptop. The app does four jobs:
- **Gets expiry money back** from wholesalers.
- **Keeps the Schedule H1 register correct.**
- **Brings chronic patients back for refills** on WhatsApp, with consent.
- **Checks every delivery bill** before you pay it.

Munshi, the built-in agent, prepares the day's work. You approve it.

RxMunshi is B2B software only. It never sells, stocks, delivers or lists medicines between retailers. Expiry returns go only to licensed wholesalers. Patients are messaged only after they have consented under the DPDP Act 2023.

---

## Try it in one minute

```bash
npm install
npm run dev
```

Open `http://localhost:3000`. Demo mode starts with no keys, no account and no internet. It loads a synthetic pharmacy, Sharma Medical Hall in Sakchi, Jamshedpur, with stock, wholesalers, refill patients, an H1 register and credit notes. Every date is relative to today.

**For the stage:** open **▶ Demo → Open Patient phone** in a second window. Send a refill reminder from **Refills** and tap **YES** on the phone. The dashboard shows the live banner and plays a chime.

## What is in this release

### From the spec

| Feature | What it does |
|---|---|
| **Split-screen Bill Scanner** (`/scan`) | Drop a JPG, PNG, WEBP or PDF bill, or capture one with the webcam. The bill stays on the left and editable rows appear on the right. Each row shows a confidence tag; rows read with low confidence are highlighted. **Save all** adds the batches to stock. Free goods lower the cost per pack. Schedule H1 and dead-stock risk are flagged automatically. |
| **Expiry Radar** (`/expiry`) | Every batch on the shelf is grouped as expired, within 30 days, 31–60 or 61–90. You can filter by voice ("Agle mahine kaun si dawai expire hogi?"), select batches and get a one-click **Expiry Return Slip PDF**. You can quarantine expired stock and export the list as CSV. |
| **Credit-note tracker** | Each return creates a pending credit note. When it is settled, the live "recovered this month" figure updates. |
| **Refills and WhatsApp** (`/refills`) | Shows chronic patients whose medicines run out within 3 days. Reminders are written in Hindi or English. A **YES** reply shows a live banner and plays a chime. **STOP** withdraws consent at once. |
| **Schedule H1 export** (`/h1`) | A Drug Inspector-ready CSV and a PDF. The CSV is protected against spreadsheet formula injection. |
| **08:00 IST daily job** | A Supabase `pg_cron` job calls the `daily-run` Edge Function. It writes the morning digest (batches crossing 90, 60 and 30 days, and value at risk) and sends approved refill templates to consented patients only. |
| **Hindi voice** | Press **V** anywhere. It uses the Chrome or Edge Web Speech API (`hi-IN`). Munshi can also speak its replies. |
| **Stage safety net** | The **▶ Demo** menu offers a sample bill, a simulated patient YES, the 08:00 job, a clock you can move forward (+1 or +7 days) and a data reset. |

### The six features that win

1. **Munshi, the agent.** Ask in Hindi (Devanagari), Hinglish or English, by voice or by typing.
   - It answers through **16 typed tools** over the shop's records and shows the source of every answer.
   - Anything that would change data becomes a **task you approve**. Each task moves through `proposed → approved → executed → verified` (or `failed`, with the reason).
   - It uses Gemini function calling when a key is set. Otherwise an **offline planner** handles the same requests with no network.
   - Munshi has a **morning plan**, an **approval inbox** with "Approve all", and an append-only audit trail.
2. **Delivery Verifier.** It checks every scanned bill against the order and earlier bills. It flags:
   - price rises since the last bill
   - rates above MRP
   - short supply
   - missing free-goods schemes
   - short-dated stock (below each wholesaler's shelf-life rule)
   - duplicate bills
   - lines that were not ordered
   - dead-stock risk
   - low-confidence reads

   It shows the rupees at stake and drafts a message to the wholesaler. On the sample bill it finds 9 problems worth ₹938.
3. **Expiry Money-Back Engine** (`/returns`).
   - Tracks each wholesaler's return window and credit %.
   - Picks the best action for each batch: *return now*, *sell first* (using sell-through and refill commitments), *plan return*, or *window missed*.
   - Chases credit notes at 15, 30 and 45 days and handles settlement, including short payments.
   - Shows recovery figures for each wholesaler.
4. **Rx to Register** (`/dispense`).
   - Scans a prescription and matches each line to stock, earliest expiry first.
   - Shows **same-salt alternatives** in stock for the pharmacist to choose from. The app never substitutes on its own.
   - Writes the **H1 entry at the moment of supply**, with the prescriber's name and address. Dispensing is blocked while a required field is missing.
5. **Committed-Demand Reorder** (`/reorder`).
   - Treats refill patients' next 14 days as guaranteed demand, adds 30-day sell-through and subtracts stock that will still be usable.
   - The **dead-stock guard** blocks a medicine that expired unsold in the last 90 days. You can override it.
   - Sends one WhatsApp order per wholesaler. The next delivery bill is then checked by the Delivery Verifier, which closes the loop.
6. **Inspector Mode** (`/inspector`).
   - A compliance score out of 100, built from seven weighted checks: licence, pharmacist registration, H1 register complete, expired stock segregated, DPDP consent records, returns closed, and purchase traceability.
   - Each failing check has a fix link, and **Fix with Munshi** proposes the fixes.
   - A one-click **inspection pack PDF** with licences, the H1 register, the expired-stock register, expiry returns and the purchase-bill index.

### Also included

- **Wholesaler scorecard** (`/wholesalers`): a reliability score from your own bills and returns.
- **Audit trail** (`/audit`): append-only, filterable and exportable.
- **Command palette** (`/` or Ctrl K): search medicines, patients and wholesalers, or ask Munshi.
- **Keyboard:** a single letter opens each section, **?** shows all shortcuts and **T** starts the jury tour.
- **Boot screen**, light and dark themes, and a layout that works at phone width.
- **Patient phone simulator** (`/phone`): it shares the demo shop across browser tabs through BroadcastChannel, so it needs no server.
- **Settings:** shop profile, the name recorded on approvals, integration status, **export everything (JSON)** and **delete shop data**.
- **Live sign-in** (`/signin`): email magic link and shop creation.

## Design

The app uses the **PoshanSetu + ReachGrid** design system and its ReachGrid workspace layout:
- Square panels with 2px ink borders and hard offset shadows; the single `hot` accent is kept for the main call to action.
- Inter Tight, IBM Plex Mono, VT323 and Noto Sans Devanagari (bundled fonts).
- Every value carries an evidence tag: `obs` (typed or confirmed), `der` (computed), `imp` (read by OCR) or `syn` (synthetic demo data).
- `tokens.css` is generated from the design system's `tokens.json` by `npm run tokens`.

## Architecture

```
Browser (Next.js 15, React 19)
  ├─ src/core       pure business logic: all arithmetic, tested; the model never produces numbers
  ├─ src/data       Store interface → demoStore (browser + BroadcastChannel) | liveStore (Supabase + Realtime)
  │                 actions.ts executes approved work and writes an audit event for each step
  └─ Munshi loop    Gemini picks tools → the browser runs them on the records → results go back
Server routes (src/app/api)
  ├─ /api/scan-bill, /api/scan-rx   Gemini vision with a strict JSON schema; the output is cleaned and limited
  ├─ /api/agent                     one Gemini function-calling step
  ├─ /api/whatsapp/send             Meta Cloud API (members only)
  ├─ /api/webhooks/whatsapp         HMAC-SHA256 signature check; only YES / NO / STOP are acted on
  ├─ /api/export/h1-csv             under Row-Level Security
  └─ /api/health                    which integrations are configured (never their values)
Supabase (supabase/)
  ├─ 14 tables + digests view, RLS through shop_members roles (owner, pharmacist, staff)
  ├─ triggers: DPDP consent before any nudge, dead-stock flag, append-only audit
  ├─ H1 constraints and a generated 3-year retain_until
  ├─ Realtime publication, private storage buckets for bills and prescriptions
  └─ pg_cron 08:00 IST → daily-run Edge Function
```

### Safety rules built in

- Numbers come from code and SQL, never from model text.
- The agent cannot act on its own. Write tools only create proposals, and approving work, or writing to the H1 register, requires the owner or pharmacist role.
- Text on bills, prescriptions and WhatsApp messages is treated as data, never as instructions. Model output is cleaned before use. Inbound replies are limited to three intents.
- The DPDP rule is enforced twice: in the app and by a database trigger.
- Paid routes are rate-limited and require a signed-in member when Supabase is configured.

## Going live

Copy `.env.example` to `.env.local`. Each integration is optional, and the app falls back when one is missing:

| Variable | Enables | Without it |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` | live data, sign-in, Realtime, webhook writes | Demo store in the browser |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | bill and prescription OCR, Gemini Munshi | sample documents and typing; offline planner |
| `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN` | Cloud API sending and the signed webhook | pre-filled `wa.me` links (owner taps send) |

To set up Supabase: apply `supabase/migrations/*`, load `supabase/seed.sql` (the drug catalogue), deploy `supabase/functions/daily-run`, and set `app.functions_url` and `app.cron_secret` as described in the second migration.

## Quality

- **52 unit tests** (`npm test`) cover expiry, returns, the verifier, reorder, H1, compliance, refills, prescription matching, Hindi, Hinglish and English intents, every agent tool, the actions on the demo store, OCR cleaning and webhook signatures.
- **Database tests** (`supabase/tests/run.sh`) apply the migrations to a real Postgres 16. They check that shops are isolated, consent is enforced, the dead-stock trigger fires, H1 constraints and retention hold, staff cannot approve tasks or write the register, and the audit trail cannot be edited.
- **End-to-end stage demo** (`npm run e2e`) runs 13 steps in Chromium: scan and verify, save, return slip PDF, a Devanagari question, "return kar do" becoming tasks, the 08:00 job with approve-all, the patient's YES reaching the dashboard live, H1 dispensing, the inspection pack, the H1 CSV, every section in light and dark, and phone width with no overflow. All 13 pass.
- The production build passes type and lint checks, and pages load about 200 kB of JavaScript on first visit (jsPDF loads only when a PDF is made).

## Known limits

- Live mode (Supabase, Gemini, Meta WhatsApp) is built and its database layer is tested on Postgres. It has not yet been run against real hosted projects with real keys.
- WhatsApp Cloud API templates need Meta business verification and template approval before refill reminders can be sent automatically.
- OCR accuracy on real handwritten bills and prescriptions has not been measured yet. The plan is to test on 10 real Sakchi and Bistupur invoices.
- The compliance score is a self-check from the shop's own records, not legal advice.
- All demo people, phone numbers and licence numbers are fictional.
